# Book downloads on skepsis

This stack is separate from the movie/TV VPN on chrysaora. Never copy its active WireGuard key here.

Private `.env` contains `WIREGUARD_PRIVATE_KEY`, `WIREGUARD_ADDRESSES`, a single `SERVER_HOSTNAMES`, `MOUSEHOLE_AUTH_PASSWORD`, and `MOUSEHOLE_AUTH_TOKEN`. Obtain the first three from a separate Mullvad device. Secrets and application state are excluded from Git.

The stack is active with a separate Mullvad device and fixed `us-dal-wg-001` relay (egress `146.70.211.120`). The owner restored MAM and reported no outstanding seeding/HnR warnings. Start all four services with `docker compose --profile torrents up -d`; the explicit profile prevents an accidental torrent-client start during initial setup.

Mousehole is available through an SSH tunnel to skepsis port 5010. Create a dedicated MAM API session using the VPN IP Mousehole reports, **ASN** locking, and **Allow Session to set Dynamic Seedbox: Yes**. Prowlarr needs its own session for its own outgoing IP. See the [upstream instructions](https://github.com/t-mart/mousehole/blob/v0.5.0/docs/getting-your-cookie.md).

Mousehole's cookie and rotated session state persist under `data/book-downloads/mousehole`. Its normal five-minute schedule handles updates; do not repeatedly press Update Now. MAM limits IP changes to once an hour across the account. Keep the selected VPN server fixed and resolve any new ASN before changing servers.

The qBittorrent entrypoint waits for a fresh successful Mousehole response matching Gluetun's current public IP before starting. This also runs after a daemon restart and can wait up to five minutes for Mousehole’s next scheduled contact. A missing/invalid cookie or an update cooldown leaves it waiting. This is a startup check, not continuous monitoring: stop book qBittorrent before deliberately changing VPN servers. Missing/rejected/stale state and rate limiting were checked with isolated tests. The live VPN kill switch blocked direct-IP traffic while the tunnel was stopped and recovered afterward. A full project recreation retained the Mousehole session, and qBittorrent waited for its next successful scheduled update.

Recreate this whole Compose project together when changing Gluetun configuration. Recreating only Gluetun can leave other containers attached to its old network namespace. Never run this project's commands in `apps/arr`.

qBittorrent is pinned to 5.1.4: BookOrbit 2.10 extracts the `SID` login cookie, while qBittorrent 5.2 uses `QBT_SID_8080` and fails BookOrbit's authenticated calls. Recheck that adapter before upgrading. The torrent port is fixed at 51413 because MAM rejects 6881. DHT, PEX, local discovery, UPnP, active-torrent queueing, and automatic ratio/time stops are disabled; the interface is bound to `tun0`. Mullvad does not provide inbound port forwarding, so peer connectivity remains limited to connections this client can establish.

BookOrbit uses `http://books-gluetun:8080` for qBittorrent and `/books/downloads` for completed files. Library imports must copy torrent payloads; editing a hardlinked EPUB can invalidate seeding. Shelfmark writes direct downloads into BookOrbit's `/books/incoming` Book Dock. `https://shelfmark.kroac.net` uses its native owner login, with the same private owner credential as BookOrbit and book qBittorrent (`data/bookorbit/admin.json`). Direct EPUB acquisition and metadata-preserving import through QM were verified live, including recovery across a Shelfmark restart. Shelfmark currently has Hardcover metadata and Prowlarr enabled, but its torrent client is blank and its Prowlarr URL is `http://prowlarr:9696`, while the shared service is on chrysaora under `/prowlarr`. This is not a working torrent acquisition route. The agreed acquisition path uses Shelfmark for direct ebooks and BookOrbit for torrents; do not silently replace owner UI changes or introduce competing acquisition paths. A standalone Shelfmark UI download does not create a paired QM request.

Prowlarr remains on chrysaora. Its separate MAM session uses public IP `68.251.135.169`, ASN locking, and no dynamic-seedbox permission. Never reuse Mousehole's rotating cookie there. BookOrbit's MAM and TorrentLeech sources and qBittorrent client are enabled; auto-grab/search/retry remain off. QM's conversational agent selects releases and its timer follows imports. BookOrbit uses category `bookorbit`; the transferred legacy seed uses `mam-legacy`. Library imports copy files, and normal torrent completion does not remove its seed. Deletion/cancellation/fulfillment actions can remove associated torrents, so review seeding before those actions.

Seed indefinitely by default. The owner's minimum is **120 hours of completed seeding credited by MAM** before any otherwise authorized removal, with no outstanding tracker obligation or HnR. Five calendar days since adding a torrent is not sufficient evidence. Keep automatic ratio, seeding-time, inactivity, and deletion limits disabled; a five-day stop timer would unnecessarily end useful seeding. A per-torrent ratio of 1.0 does not override the time minimum. qBittorrent's `stalledUP` state means an available seed with no active upload, not a stopped torrent. Use the tracker to verify credited time before cleanup.

Before every charged MAM grab, check the live account and the whole pending batch. Prefer verified freeleech or a confirmed personal freeleech wedge applied before acquisition. Preserve a projected account ratio of at least **2.0** as a buffer above the owner's stated MAM minimum of 1.0; account for active downloads, queued selections, and traffic not yet reflected in tracker totals. Hold a grab if its effective charge or remaining allowance cannot be established. The owner authorizes existing wedges and bonus-point upload-credit redemptions as needed to build room, with current store terms checked before spending. Target at least 10 GiB upload buffer and retain 2,500 bonus points. The detailed selection instructions live in QM's book-domain README. This is a conversational selection rule, not an app-enforced limit on manual UI grabs; BookOrbit's automatic acquisition remains disabled.

`mam-health.py` checks account ratio, upload buffer, bonus balance, and wedges through the local host's home internet connection. On October 2, skepsis, chrysaora, and sophon-media were verified to share the registered public IP, so the obsolete SSH relay through chrysaora was removed. Keep this host-level monitor outside the downloader VPN. It requires a **third, dedicated API session** for `68.251.135.169`, ASN locking, dynamic-seedbox permission No, labelled `book account monitor`. Save only its cookie to `data/book-downloads/mam-account-cookie`, mode 0600. Account reads themselves rotate `mam_id`, so the monitor atomically persists the replacement cookie. Never share Prowlarr's or Mousehole's session. Other native account/metadata/wedge operations must acquire `mam-health.lock` and preserve rotation too.

The `mam-health` user service/timer files are installed and the hourly timer is enabled. The dedicated session is supplied; its first live account check passed and persisted the rotated cookie with mode 0600. Start an immediate check with `systemctl --user start mam-health.service`. Inspect `data/book-downloads/mam-health.json` or `journalctl --user -u mam-health.service`. Low reserves and bonus-redemption opportunities produce an actionable snapshot and failed service status. This monitor does not send messages, acquire torrents, or spend points itself. Failed checks retain the last successful snapshot explicitly marked stale. Five isolated tests cover thresholds, invalid responses, session rotation, and private output without contacting MAM. The [owner's linked discussion](https://www.reddit.com/r/trackers/comments/166n2p0/building_ratio_on_mam/) motivates keeping freeleech seeds for bonus income; verify current tracker limits before adding any batch.
